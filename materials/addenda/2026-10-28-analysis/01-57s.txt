### 1\. 势函数：现有策略已经有基础，但比较得还不够远

我检查了当前 [`strategy.cpp`](https://github.com/Frank-678/RoboMaster-Turing-Competition-BeyondControl/blob/strategy/visible-resource-bfs/src/rmtc_bot/src/strategy.cpp?utm_source=chatgpt.com)。

目前的资源评价大致是：

```cpp

consider(

    node.first,

    benefit * freshness / (node.distance + 1),

    "collect_resource"

);

```

这相当于：

U=\\frac{\\text{资源的预期收益}\\times\\text{信息新鲜度}}

{\\text{路径长度}+1}

它已经比简单地寻找最近资源更合理，也考虑了资源得分封顶、任务奖励以及历史观测过时的问题。

但是，它主要评价到达某个目标的价值，并未充分评价到达之后的局面。

比如有两条路线：

* 路线 A：3 Tick 后拿到价值 20 的高级资源，但随后陷入敌人包围。

* 路线 B：4 Tick 后拿到价值 10 的普通资源，但下一步还可以取得另一个资源，并靠近任务目标。

只看单个目标，A 很可能被选中；把未来行动一起考虑，B 则可能更好。

我们应当考虑：

\\boxed{

U(s,a)=

\\mathbb E\[\\Delta S\]

+\\lambda_I I(s,a)

+\\lambda_P P(s,a)

-\\lambda_R R(s,a)

}

其中：

* ：按正式计分规则计算的预期得分变化。

* ：探索未知区域带来的信息价值。

* ：到达更有利的后续战略位置的价值。

* ：死亡、争格失败和失去行动机会的风险。

这里的权重是需要赛前验证的设计参数，不能直接当作已经得到的最优值。

更重要的是，应该尽量利用现有 `score_delta()` 的官方计分边际收益，而不是重新发明与规则不一致的分数体系。

### 2\. Beam Search：最直接的算法升级

现有 `Strategy::decide()` 使用 BFS 寻路，然后评估候选目标，选择效用最高的第一步。

它没有在资源争夺和攻防决策上，系统地保留多条未来行动分支。

这正是 Beam Search 可以补充的部分。

RMTC 中三步前瞻的示意

假设初步采用搜索深度 、束宽 。注意，这只是一个待测试的起点，不是冠军参数在 RMTC 中已被证明有效。

每个 Tick：

* 根据实际感知生成合法动作候选。

* 用本地规则模型推演后续状态。

* 对未知对手动作使用有限数量的情景假设，而不是当作确定事实。

* 保留评价较好的候选状态。

* 只执行最优计划的第一步；下一 Tick 收到真实感知后重新搜索。

这就是滚动时域规划（Receding Horizon Planning）。

它适合 RMTC，因为环境会不断变化，不应当像 AHC 那样预先生成一整局的固定操作序列。

### 3\. 历史操作优化：只能优化未来，不能修改过去

冠军的 Retroactive Insertion 可以回头修改尚未最终提交的 AHC 操作序列。

RMTC 不能这样做，因为已结算的 Tick 无法撤销。

但我们可以维护一个短期目标或行动计划，并在新信息出现时重新规划尚未执行的部分。

例如，机器人原本打算沿一条路线前往堡垒，途中发现高级资源。新的计划应该比较“继续前往堡垒”“先取资源再前往堡垒”和“放弃堡垒转向其他目标”，而不是仅仅根据本 Tick 哪个格子最有吸引力来决定。

这还能解决一种常见问题：目标振荡。如果两个目标评价接近，算法可能今天向左一步、下一 Tick 又向右一步。

可以引入合理的目标切换成本（hysteresis），但遇到确定危险、目标失效或重大收益变化时仍立即重规划。

### 4\. 已经存在的时间动态规划，不应重新实现一遍

### 二、冠军最关键的三个改进

### 1\. Beam Search：不再只保留一种选择

你的程序每次挑出一个目标卡片，就立即决定固定它。

冠军的 `solve_beam()` 不同。它维护多个候选棋盘状态，并尝试不同的目标选择。

源码中的主要参数是：

```cpp

const int beam_width = 5;

const int target_branch_count = 3;

```

也就是每层最多保留 5 个搜索状态，每个状态尝试最多 3 种后续选择。

而且它使用 `prune_diverse_beam()` 保持候选多样性，避免所有搜索分支都集中到几乎相同的策略。

### 2\. Retroactive Insertion：修改过去的操作

这是整份冠军源码中最值得研究的部分。

普通构造算法只能这样生成操作：

A\\rightarrow B\\rightarrow C\\rightarrow D

但冠军允许重新考虑以前的操作序列，在中间插入一个操作：

A\\rightarrow B\\rightarrow \\boxed{X}\\rightarrow C\\rightarrow D

这样做可能让某张卡片一步跨越多个原本需要的移动，也可能触发历史操作的抵消或合并。

源码中有：

```cpp

static constexpr int RETRO_WINDOW = 500;

```

它会回看最近最多 500 次操作，寻找值得插入新操作的位置。

这不仅是贪心，而是借助排列的复合运算与共轭变换，在保持操作合法性的同时重新安排历史动作。

### 3\. Operation Local Search：对完整操作序列做代数优化

冠军最终还有一个你没有的独立模块：

`OperationLocalSearch`

它会尝试消除冗余操作。

例如，因为矩形交换是一个对合操作，执行两次完全相同的交换就会恢复原状：

A^2=I

因此：

A\\circ A=I

相邻的两个相同操作可以直接删除。

而更复杂的 `conjugate_operation()` 可以通过合法的等价变换调整操作顺序，使原本不相邻的操作有机会合并或相互抵消。

这里实际上已经涉及置换群与代数化简。
