## 设计提案（未实现）

harness指模型周围的程序控制：构造允许输入、调度请求、校验结果、接纳有效状态、本地执行和反馈记录。单个Prompt堆叠角色标题不等于完成工程分层。

| 层 | 职责 | 验收 |
|---|---|---|
| 规则/上下文 | 固定v1.1、公开观测与事件原文、session/tick | 无内部真值或其他队感知；来源与版本可追溯 |
| 官方LLM语义 | 理解原文，给结构化提案及对应原文片段 | 不能以正则/关键词替代LLM；不要求大量自由推理文本 |
| 校验/状态 | 类型、区域、起止Tick、未知项、重复和过期 | 格式合格不等于语义正确；跨场结果拒绝 |
| 本地控制 | 有效效果状态＋最新D/任务→合法动作 | 500ms控制继续运行，模型迟到时本地兜底 |
| 反馈/评测 | 原文、Prompt版本、解析、错误、延迟、last_action | HTTP资格、格式、语义、动作与收益分别统计 |

本地契约可有source_text_hash、session_id、announcement_tick、event_kind、region、starts_at、expires_at、uncertain_fields；这是自拟接口，不是官方固定返回。500ms是动作周期，不是LLM耗时承诺。同一公告重复不重复调用，同Tick不同公告不能丢。每公告采样k次，N份公告至少Nk次请求，另有任务、资格确认与重试；预算按当场公告，不能把暂定100永久硬编码。

## 采用与否决

| 方案 | 处理 | RMTC依据或限制 |
|---|---|---|
| 明确输入/输出、少量真实代表例 | 采纳设计/待测 | 例子符合v1.1；评测语义和边界，不只检查JSON |
| ReAct反馈结构 | 适配 | 读公开回执再调整，不逐Tick串行等模型或开放任意工具 |
| Self-Consistency默认多请求 | 暂缓 | 原摘要收益不保证RMTC效果，先测准确率、预算与延迟 |
| ToT每Tick模型搜索 | 否决默认采用 | 当前低延迟基线与配额；本地有限搜索另测 |
| 任意网页RAG/本地向量模型 | 否决直接搬用 | 允许信息、官方网关和本地模型禁令；合法规则可做普通文本索引 |
| 赛中自动改Prompt | 否决 | 可封存前离线比较；赛中遵守版本封存与登记切换 |
| 本地策略语言模型/内嵌权重 | 否决 | 不借Prompt优化名义绕过禁令 |
| 生成常识补未知事件参数 | 否决 | 参数来自本场公告，缺项标未知，不造规则 |
| 长角色/历史采样参数保证收益 | 不采纳效果保证 | 以本届模型的准确率、延迟与对局为证据 |

这些是基于赛事约束的工程判断，不是论文作者对RMTC的结论；不把历史模型规模经验套成2026官方服务保证。

评测先固定公开事件样本、规则真值和版本，按事件划分调参/验收集，核对区域、起止、免疫、死亡奖励。比较简单结构化、少量示例、必要的有限复核，报告语义准确率、未知处理、调用数、输出长度与延迟。再测暂停恢复、跨场迟到、429分类、非完整响应和新公告覆盖；最后同地图/席位/对手配对。无改善保留已验证简单版。当前未调用正式模型或实现参赛bot。
