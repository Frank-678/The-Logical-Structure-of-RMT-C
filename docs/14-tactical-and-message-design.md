# 战术取舍与ROS消息处理：编码前设计说明

来源：RULES-02 §§4–8、10–11；PROTO-02 §§2–4；[来源索引](../REFERENCES.md)。堡垒坐标及世界分裂保护另见[QA-02/CHAT-06](13-qa-and-fortress-2026-10-25.md)。本页整理规则推导与设计建议，不表示机器人已实现、引擎行为已验收或策略胜率已测量。

## 1. 战斗先于移动，移动意图不能当作逃脱

RULES-02 §5.2：本Tick先处理事件，再设置防御，按移动前位置同时结算普通/无双攻击、反伤及死亡；存活者随后移动，移动触发辣椒等入点事件。双方正常攻击同时结算，允许互相击毁，不按消息先后排开火顺序。

| 场景 | 规则结果 | 对候选评价的要求 |
|---|---|---|
| 当前位于敌方射程，准备移出 | 先受本Tick攻击；死则移动取消 | 不把MOVE算成当前普通攻击的闪避 |
| 当前不在射程，随后移入 | 不被本Tick已结算攻击补打 | 检查下一Tick威胁及移动后环境伤害 |
| 双方同Tick致命攻击 | 可以互相击毁 | 各自先计算攻击贡献和奖励，再扣死亡 |
| 世界分裂激活时站在线上 | 移动前死亡、立即复活、强制WAIT | 必须在激活Tick之前离线，不能依靠当TickMOVE |

普通攻击只命中指定方向直线1–2格内最近的存活敌车。距离1和2各有一个敌人时只打距离1目标；最近目标有出生保护也挡住后方目标，自身伤害为0。障碍不阻断攻击。天下无双改为自身周围横纵±2格内全部敌人，包含斜向；方向仍须合法，但不限制该目标集合（§6.2、§8.5）。

## 2. 杀伤、击杀与死亡不是同一种分数

RULES-02 §10.2：设本Tick实际攻击贡献为A、击杀奖励为K、死亡次数为n，则D'=max(0,D+A+K−60n)，对抗分为C(D)=15min(D/500,1)。普通攻击/无双按实际损血增加A；反伤和辣椒损血不计A。每个死者的K总量60，由致死批次的合格贡献队伍去重均分，历史Tick攻击者不参与。

| 原因 | 造成伤害一方 | 死亡一方 |
|---|---|---|
| 普通/无双攻击未击杀 | 增加实际攻击贡献A | 仅损HP不因此扣D |
| 普通/无双攻击击杀 | A及分得的K | 每死一次扣60D |
| 反伤击杀 | 合格防御方分K，反伤本身不计A | 每死一次扣60D |
| 辣椒击杀 | 合格触发队伍分K，火线本身不计A | 每死一次扣60D |
| 爆炸/世界分裂死亡 | 无K | 每死一次扣60D |

推导例子：独自攻击20HP目标并击杀，增加20+60=80D，未封顶时增加2.4分；两队各打名义20、目标剩10HP，各得实际5和奖励30，即各35D。双方各剩20HP且互杀，各自增加20+60−60=20D。普通与反伤同批致死时须按规则分配实际损血，不能把所有名义伤害都计为攻击贡献。

没有新增贡献/奖励时，D=100死亡降为40，对抗分减少1.8；D=520降为460，减少1.2；D=600降为540，对抗分仍15，但同分比较D减少60。不能每次死亡都固定扣1.8总分，也不能因曾超过500就永久认为对抗项已满。客户端采用感知中的最新score.effective_damage，不能重复加减。

资源和已完成任务保留。普通死亡有复活等待和位置代价，世界分裂立即复活但损失当前位置及该Tick行动；两者不能用同一固定时间成本替代。世界分裂虽有公告，材料未统一保证至少提前多少Tick预警，能否避免取决于公告、路径及当时状态，不能认定所有死亡都是失误或全部是运气。

## 3. 火爆辣椒：移动后的收割与逼位

RULES-02 §8.7：每次成功移动进入公告点触发该Tick整行整列火线，交点车辆不受该条火线伤害；线上其他存活车辆受50HP，障碍不挡、防御不减，出生保护免疫。生成时站在点上或持续停留不触发；离开再进入可再次触发。全部辣椒火线同Tick统一结算；触发者可能被其他火线伤害，战斗阶段已阵亡者不重复产生辣椒击杀奖励。

示例：点在[5,5]，自己在[5,4]，敌人在[8,5]且40HP。提交向下MOVE，只有自己活过普通战斗并成功进点，且敌人移动后仍在火线且无保护，才可能火线击杀。若只有自己为该死者的合格触发者，获得60D奖励；敌人若剩100HP，仅烧伤不直接增加D。

设计建议/待测试：候选踩点必须检查当前普通战斗生存、可入点性、争格、目标移动后位置、保护状态、其他火线及资源机会成本。优先评估残血收割、多目标击杀、迫使对手离开资源点或中断堡垒驻留。不能因为远处敌人在同一行就当作实时可见；只用合法感知、历史记忆和公开公告，并标注不确定性。

反复离开/进入需要多个Tick且消耗行动，敌人也会调整，不能把持续踩点视作无成本持续伤害。多个触发者参与同一击杀会均分奖励，须按不同目标分别计算期望收益。

## 4. 堡垒争夺：九格驻留与增益兑现

CHAT-06范围为x、y各11–13，中心[12,12]。§8.5驻留判定在战斗后、移动后：存活且在堡垒内才累计，连续10Tick达标；未完成时离开或死亡清空。获得增益后可离堡，死亡复活也保留，到堡垒结束统一失效。战斗后才达标，不能令达标Tick已经结束的攻击升级。

推论/待测试：中心没有额外驻留加成，不要求站定某一格。堡垒内换位可维持驻留，但目标格占据、争格、当前普通攻击和移动后事件都须检查。不能只按离中心距离来评分。

驻留中DEFEND能减少普通受击，但不能移动、攻击，也不减免辣椒/爆炸；反伤事件、无双攻击和出生保护需要分别判断。离开保命会损失尚未完成驻留，原地硬守则可能死亡，不能设置无条件“最后一Tick必须守住”。

工程上可评估：抵达时间、完成10Tick的生存概率、堡垒剩余寿命、拿到增益后预计可攻击的次数与目标数量、对手取得增益的风险、绕路放弃的资源/任务。普通攻击20→无双50只对适用非防御目标成立，防御目标无双仍10；不能把增益固定估值为每次多30HP。没有可信对手状态时，使用情景区间而非伪造确定概率。

## 5. 暂停恢复、定位与幂等处理

PROTO-02 §§3–4：session_id区分场次，tick区分该场逻辑步。一帧是状态消息，不是视频帧，也不是坐标系frame。暂停恢复后依据重新发布的感知提交；同Tick重发可以重发缓存动作，但不能把策略、计时或路线进度推进两次。早于当前Tick的感知丢弃；新场次清理旧规划、事件和缓存。

例：第20Tick选“右”，未结算时暂停；恢复又收20，不代表已经移动，应核对感知并可重发该Tick缓存“右”。收到21后再看当前位置和last_action，不能直接假设移动成功。self.position是当前位置依据；last_action用于解释上一步，不能累计推算位置。漏帧/重启后可从新感知恢复定位，但不能声称所有历史事件记忆自动恢复。

本地异步任务建议记录session_id、提交tick、来源事件标识/文本哈希、有效期。AI结果返回时先核对场次与适用性；旧Tick结果不得直接发布成当前动作，仍有效的事件理解可经复核更新当前效果状态。不要把“同Tick感知去重”错误扩展成“同Tick只处理一条公告”：可能有多个不同公告。

每Tick最多执行一个动作；截止前可以更新候选，最后候选按协议接收检查与结算状态检查处理。工程默认一次经校验提交有助于减少积压，但不是把规则改成每Tick只能发布一次。重发不等于重复执行；幂等性须由业务状态管理实现。

## 6. ROS术语与本场QoS契约

Topic为具名消息频道；裁判发布/team_X/perception，机器人订阅；机器人发布/team_X/action。消息到达后由回调处理，Executor调度回调。等待网络AI应放到不阻塞感知/动作的异步流程；多线程本身不解决旧结果、状态竞争和过期动作问题。

PROTO-02 §2给定：

| 话题类别 | 可靠性 | 持久性 | 历史深度 |
|---|---|---|---|
| 感知、动作 | RELIABLE | VOLATILE | 1 |
| 注册、任务、队伍名录 | RELIABLE | TRANSIENT_LOCAL | 1 |
| 事件公告 | RELIABLE | TRANSIENT_LOCAL | 128 |

RELIABLE提供可靠传输机制，不等于动作必在截止前送达。VOLATILE不要求向后来加入者补历史。TRANSIENT_LOCAL由发布者保留相应历史供匹配的后来订阅者接收，不等于永久磁盘保存。KEEP_LAST深度1限制相关历史缓存，不会清除程序自行维护的队列或中断已经运行的旧计算。发布/订阅QoS须匹配正式契约，不能把事件也统一设成深度1。事件重放还要核对场次、去重与生效期限。

术语解释补充来源：[ROS 2官方QoS文档源码](https://github.com/ros2/ros2_documentation/blob/rolling/source/ROS-Framework/interfaces/topics/About-Quality-of-Service-Settings.rst)。比赛实际使用Humble，具体接口和运行行为仍须在目标环境验收；此处不声称已经实机验证DDS。只收到感知不能证明动作反向通路正常，必须核对真实last_action回执。

## 7. 最小实现与验收队列

以下为待执行用例，未标运行通过：

| 用例 | 预期检查 |
|---|---|
| 同Tick感知重复/暂停恢复 | 路线不二次推进，可按契约重发缓存动作 |
| 漏Tick、延迟旧感知、新session | 用最新绝对坐标恢复；旧状态不污染新场 |
| AI跨Tick或跨场返回 | 结果核验适用性，不发布旧动作 |
| 同Tick多个事件及晚加入事件历史 | 不丢不同公告，不重复应用同公告，不恢复过期效果 |
| 射程内MOVE和射程外移入 | 分别先受击/不受已结算普通攻击 |
| 近保护敌车、远无保护敌车 | 普通攻击不穿透近车；墙不挡弹 |
| 辣椒残血、保护、目标移出、多火线 | 分别检查击杀奖励、免疫、未命中、统一批次 |
| 堡垒九格内部移动及离开再进 | 驻留递增/清空；达标后下一可用攻击才兑现增益 |
| 分裂复活与普通复活 | 立即/等待、强制WAIT、保护和60D罚分分别核对 |

参数化与离线调优见[QA说明](13-qa-and-fortress-2026-10-25.md)。先把规则与通信实现正确，再搜索少量权重；不能用优化器弥补错误结算或把名义伤害当实际收益。
