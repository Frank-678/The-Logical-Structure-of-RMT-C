## 1. 新工具究竟能做什么

已完整阅读EDITOR-01的324行HTML/CSS/JavaScript（28,159字节）。它是浏览器单文件栅格地图编辑器，静态代码没有外部脚本、CDN、fetch、WebSocket或后端依赖；导入通过文件选择、导出通过本地Blob下载、复制使用剪贴板及回退方案。未发现自动保存到localStorage的逻辑，关闭前应导出。

默认地图24×24，默认第二阶段四席位出生点为[1,1]、[22,1]、[1,22]、[22,22]；第一阶段只用A。尺寸可改1–200，资源绘制默认10/20，支持障碍、资源、清空、出生点、缩放、拖画和最多60次历史撤销。编辑器默认值不证明正式地图的尺寸或出生点已经公布。

键盘1画障碍、2画普通资源、3画高级资源、D清空格子、A导出；清空保留出生点。使用电脑鼠标更适合。原件只归档不改写，不把作者原代码当本队原创实现。

## 2. 导出格式与本地测试端的对应

| 输出选择 | 实际字段与行为 | 本包可否直接作为完整配置 |
|---|---|---|
| 正式裁判地图 · map + robots | 只有map、robots；缺stage/events/missions等 | 不应直接当作完整配置，测试网页导入会要求stage |
| 测试裁判完整配置 | 含stage、vision_radius、respawn_wait、spawn_protection、mission_text、missions、events、map、robots | 新建默认输出已通过DIST-02 validate_config；完整对局待验 |

EDITOR-01 `buildOutput`已经提供practice模式。CHAT-07说“输出格式换成测试裁判端就行”，与原件下拉框对应，不意味着必须改HTML源码。标题中的“正式裁判导入”、100KiB及任务[12,12]是编辑器内提示，尚未独立核对正式管理端实现，不能据此让选手访问正式管理接口。

新建practice模式任务数组为空，events.enabled=false。因此仅画地图后导出，会得到没有事件和任务的练习，不能证明事件理解、任务得分或真实AI资格链路已验证。

导入带stage的完整配置会克隆为template，随后修改map/robots，保留原来的其他字段（任务、事件、文本、额外参数）；geometry导入没有stage则不作为完整模板。地图障碍、资源数组会重新按y/x顺序输出，资源ID/坐标/数值语义保留，不保证文件字节或数组原顺序不变。robots输出按本阶段席位列表重建，导入时机器人额外字段不一定保留。

测试端接入位置：DIST-02 `index.html` 的import要求stage=1或2；部署时把完整config送入`practice.py:Practice.start`，后者调用bin/validate_config。Tick时长、总Tick、陪练选择属于测试端部署设置，不由编辑器的map对象自动决定。

## 3. 推荐操作顺序

1. 先在测试裁判网页选择阶段，展开“地图、任务与事件配置”，导出完整配置。
2. 在电脑浏览器双击EDITOR-01原件，导入上一步JSON；格式选择“测试裁判完整配置”。
3. 修改地图与出生点，核对资源数量、价值及可达性；需要正式规模测试时按正式规则调整，不能把空白地图当正式赛场。
4. 导出JSON，回测试端导入；复核missions、事件点位/矩形、时间安排、堡垒范围、分裂线和出生点约束，再部署新练习。
5. 保持自己的席位不勾为陪练，确认自有程序收到感知、发出动作并收到last_action；再进行完整对局及真实LLM验证。地图编辑器不替代机器人程序。

不要直接拿练习18×18的旧事件坐标与数值当正式参数。DIST-02模板依然是练习版，部分伤害/驻留时长与RULES-02不同，详见[发行包核对](12-v1.1-package-audit.md)。改变地图尺寸后，不能仅因导出成功就认为原任务/事件仍适配。

## 4. 实际检查与未覆盖范围

[测试脚本](../scripts/check_map_editor.mjs)在Node vm中执行原始内联JS，以最小DOM替身和测试入口调用parseImport、geometry、buildOutput；原件未改动。检查默认两种输出、两阶段模板往返、资源ID/坐标、缺席位、外置事件拒绝、reach任务越界等，13项通过，见[逻辑结果](../checks/map-editor-logic.json)。两项检查特意复现已知边界，通过表示已复现，不表示编辑器拒绝了它们。

往返比较先对地图障碍/资源数组做坐标归一，确认语义一致；最初逐数组顺序比较观察到重排后，改成上述明确的比较口径。没有修改原始逻辑去迎合测试。

[默认新建practice输出](../checks/map-editor-fresh-practice.json)通过[包内校验器结果](../checks/map-editor-validator.json)，returncode=0。只运行了配置验证，不启动ROS裁判/网页/模型，不证明完整游戏、浏览器鼠标交互、手机触控、剪贴板和下载权限都正常。

仍需注意：

- 事件定义内的越界坐标不会被编辑器全面拦截；已复现辣椒点[999,999]可导入导出。部署前交由实际校验器并人工复核事件全部约束。
- 绘制UI不允许在资源上放出生点，但导入检查仅排除出生点与障碍重叠，允许资源与出生点同格。这里记录编辑器路径差异，不据此断言赛事一定允许/禁止；按正式输入规范及裁判验证。
- 编辑器不保证资源总值200、12普通+4高级、连通性、出生点公平或事件适配。到达任务只检查坐标合法与障碍重叠，不证明路径可达。
- 导入完整配置后切换比赛阶段会保留template原任务/事件，须再次核对；测试端第一阶段另会强制清任务并关闭事件。
- 编辑器导入上限5MiB，测试网页为1MiB，正式模式提示100KiB且导出仅警告不阻止；各入口限制不同，不能混用。
- 导出后没有自动持久化；撤销历史不是关闭后恢复功能。

## 5. 可用于赛前测试的地图组（设计建议，待对战）

| 场景组 | 关注问题 | 控制变量 |
|---|---|---|
| 对称资源/换席位 | 采集效率与起点偏置 | 资源总值、通路长度一致 |
| 单格通道/死路 | 寻路、占位、争格和脱困 | 固定对手策略后改变瓶颈 |
| 直线距离1与2双目标 | 最近敌车阻挡、出生保护、墙不挡攻击 | 固定HP、站位和双方动作 |
| 辣椒行列交叉 | 移动后伤害、多火线、击杀均奖 | 固定触发Tick及保护状态 |
| 堡垒九格驻留 | 内部移动、打断与增益兑现 | 区分正式10Tick与练习默认4Tick |
| 世界分裂/爆炸路线 | 提前避险、立即复活保护及扣分 | 改公告提前量，不把练习5Tick写死 |

编辑器有助于制作不同地图、留出未调参场景，不能仅在一张图上优化后宣称泛化。人工准备练习地图可用全图；在线机器人输入仍限公开合法感知，不能读该配置、观赛网页或内部日志当实时真值。

## 6. 现场操作通知的影响

CHAT-08可见：预计比赛需至少5小时、至多9小时，建议队友互相替补；赛前1–2天计划提供参赛示例视频；替补“最起码会启动和填令牌”，有多策略还需会切换策略。时长是群内预计，不当作准确开闭场时刻；视频尚未附上，不声称已经阅读。

这不是批准现场任意改源代码、Prompt或参数。按RULES-02 §2.3及QA-02：先实现并封存登记decision_type，人工切换须按暂停/申请/次数限制执行，填令牌只更新裁判分配接入信息，不能夹带临场动作。第一阶段后统一调整窗口另计，不能扩展为随时调整。

建议两人都能独立完成：启动环境与已封存程序→填写本场席位/域/网关/令牌→确认真实动作回执→核验AI成功→按批准流程切换登记策略→登记异常重启→保存证据。令牌不提交仓库、不录入公开截图。替补是否必须同时到场、现场能否换电脑等细节截图没有完整明示，不自行补成官方许可。
