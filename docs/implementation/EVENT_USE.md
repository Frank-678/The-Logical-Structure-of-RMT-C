## 为什么增加日志

HTTP成功与事件被策略采用是两条不同事实。新Session提供event_diagnostics，主线程消费回包时记录request_tick和received_tick；换场清空，同Tick缓存不会重复累计。Bot在回包数变化时写一次event_update，避免每Tick输出整份解释。

| 字段 | 准确含义 |
| --- | --- |
| replies / validated / rejected / partial | 已消费回包、完整契约通过、拒绝、含unknown的部分解释；HTTP错误/模拟回复也可能计入拒绝 |
| imported / known | 累计合并条数（含重复解释）/ 当前独立事件键数量；不以条数假装事件收益 |
| after_start / arrived_expired | 采纳Tick晚于事件起点 / 已到事件end；到期点事件仍可能需要重建其已领取效果，不一律删除历史 |
| request_tick / received_tick | 来源与主线程消费的逻辑回合；不是HTTP毫秒或模型推理Token |
| last_error / last_events | 固定错误分类与最近通过的事件参数；不输出原文source、模型思考、密钥 |
| pending / active / expired / empowered | 已校验解释在当前Tick的阶段，及依据本车实际历史重建的无双状态 |

run.sh现在同时保存机器人输出到项目log/bot_时间_进程号.log；无需手工加tee或额外环境变量。不要只上传裁判run_dir而漏掉外部启动的A端日志。日志只供赛后诊断，不反馈到比赛决策输入。
